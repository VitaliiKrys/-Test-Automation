# Лабораторна №5 — REST API / Supertest / JSON Schema / Postman / Newman (варіант 9)

Виконано навчальний Express API з фабрикою `createApp()`, окремим станом для кожного тесту, автентифікацією Bearer token, правами власника замовлення, створенням, переглядом і видаленням замовлень.

**Варіант 9:** `POST /orders` із заголовком `Idempotency-Key`: ідентичні повторні запити не створюють дублікати, повертають той самий id; інший payload з тим самим ключем викликає 409; ключі різних користувачів незалежні.

## Запуск

```sh
npm install
npm test
npm run coverage
npm run typecheck
npm start
```

В іншому терміналі (під час роботи сервера):

```sh
npm run postman
```

Результат Newman (JUnit XML): `results/newman.xml`.

У `tests/` — параметризована валідація, 5 рівнів перевірки API, доступ без токена/з підробленим токеном/до чужого ресурсу, JSON Schema з `additionalProperties: false`, перевірка 204 і кінцевого стану сховища. У `postman/` — готова колекція з Login, Create, Repeat, Get.

Колекція запускається з Newman після `npm start`. Встановлення залежностей потрібне для запуску Vitest, Supertest і Newman (Node.js 20+).


## Якщо частина тестів падає

1. У терміналі в каталозі **цієї** лабораторної виконайте `node -v` (потрібен Node.js 20+), `npm install`, тоді `npm test`.
2. Перевірте типи окремо: `npm run typecheck`.
3. Для Postman/Newman спочатку запустіть сервер командою `npm start` і **не закривайте** це вікно. Відкрийте другий термінал і виконайте `npm run postman`.
4. Якщо порт 3000 зайнятий або працює інша лабораторна, зупиніть старий процес. Postman має звертатися саме до API лабораторної №5.
5. Запускайте колекцію **повністю і в порядку**: авторизація → створення → повтор → читання → конфлікт → список. Якщо запускати лише один запит, змінні `token`, `orderId` та `idempotencyKey` можуть бути не задані.

**Виправлення у версії 2:** останній сценарій Postman більше не вимагає, щоб на запущеному сервері загалом було тільки одне замовлення. Тепер він перевіряє, що *поточне замовлення* присутнє рівно один раз. Це усуває хибне падіння після повторних запусків колекції без перезапуску сервера. Додано регресійні тести на потрійне повторення запиту з одним ключем і звичайне створення без ключа.

Якщо у Vitest залишаються червоні тести, надішліть **вивід команд `npm test` і `node -v`** — це дозволить перевірити конкретну помилку на вашому комп’ютері.
