# Експеримент: перевірка стану проти перевірки викликів

**Початковий стан.** `OrderService.placeOrder()` один раз викликає `repo.save(record)`.

**Тимчасова зміна.** Замість одного збереження виконати два виклики:

```ts
await this.repo.save({ ...record, status: 'draft' } as OrderRecord);
await this.repo.save(record);
```

**Спостережуваний ефект.** Підробка на базі `Map` зберігає кінцевий запис; перевірка стану `findById` проходить. Тест зі шпигуном `expect(repo.save).toHaveBeenCalledTimes(1)` упаде, бо викликів два.

**Висновок.** Перевірка стану зазвичай стійкіша до змін внутрішньої реалізації. Перевірка взаємодії виправдана для зовнішньої доставки повідомлення або інших дій, які не мають доступного локального стану.

Після експерименту повернути звичайне одноразове збереження. Не залишати навмисно падаючий тест у фінальному наборі.
